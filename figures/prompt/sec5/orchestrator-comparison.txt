USER CONTEXT PROMPT

Use case: scientific-educational
Asset type: concept figure for a Chinese undergraduate cloud computing textbook
Primary request: Create a side-by-side architecture comparison figure showing how Kubernetes decomposes the Swarm Manager's monolithic role into specialized independent components. The figure must make ONE thing visually obvious: Swarm has a single control entity doing everything, K8s has multiple independent components each doing one thing.

Source context from the textbook:
In Swarm, the Manager node simultaneously handles: receiving deployment requests (API), storing cluster state (built-in Raft storage), making scheduling decisions (which node gets which container), and health checking (detecting failed containers/nodes). This works for small clusters but becomes a bottleneck at scale because responsibilities are coupled. Kubernetes decomposes this into: API Server (single entry point for all operations), etcd (distributed state storage), Scheduler (placement decisions only), and Controller Manager (runs multiple reconciliation loops). On the data plane, each node runs a kubelet that talks to API Server to know what to run and reports health status back.

Teaching goal:
Show the architectural decomposition clearly: one monolithic Manager (Swarm) vs four independent specialized components (K8s). The reader should immediately understand WHY this decomposition helps: each component can be scaled, replaced, or upgraded independently.

Beginner misconception to prevent:
The figure must NOT show K8s as just "a bigger Swarm" or "Swarm with more nodes". The structural difference must be visually clear: inside the Swarm Manager, responsibilities are packed together; in K8s, they are separate boxes with clear boundaries.
