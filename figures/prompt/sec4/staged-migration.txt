Figure contract

Why this figure exists:
The figure explains how a stateful online service migrates a session without creating two simultaneous writers. It must show that transferring critical state is not enough: the source first freezes new writes and drains in-flight work, the target prepares without serving, and only an epoch-protected ownership transfer allows the target to activate.

One teaching question:
How can a session move from a source server to a target server while preserving one authoritative writer, then fill non-authoritative state in the background?

Beginner misconception to prevent:
Students must not think that receiving the first state wave immediately authorizes the target to serve. Prepare and Activate are separate states, and Activate occurs only after ownership transfer. Students must also not think that authoritative gameplay state may be postponed to later background waves.

Diagram role:
Five-stage timeline plus state-ownership lifecycle.

Required mechanism:
1. Prewarm the target with static resources while the source remains active.
2. Begin handoff on the source: stop new writes, drain in-flight requests, and create epoch n.
3. Transfer all authoritative state to the target. The target enters Prepare(epoch n), reports ready, but remains unable to serve.
4. Transfer the lease or routing ownership to the target with epoch n. The target executes Activate(epoch n), the source rejects the old epoch, and client service resumes only here.
5. Fill only derived views and rebuildable caches in the background.
