Source context from the textbook:
The section introduces Docker Swarm as the step between single-machine Compose and Kubernetes. A game backend with four components (PostgreSQL, Redis, lobby-api, gateway) is deployed to a three-node cluster (1 Manager + 2 Workers). PostgreSQL and Redis are business tasks constrained to the Manager node in this teaching example; they are not part of the Manager control plane. lobby-api and gateway each have 2 replicas distributed across the Workers. When Worker-A fails, Manager detects the lost stateless replicas and starts replacements on Worker-B, maintaining the desired replica count. The stack services communicate through an overlay network that provides cross-node DNS resolution using service names.

The reader should immediately see: (1) Manager has a global view and makes placement decisions, (2) Manager control role is different from business tasks running on the Manager node, (3) service tasks on different nodes are logically connected by the overlay network, (4) Worker failure triggers automatic recovery for lost stateless replicas without human intervention.
