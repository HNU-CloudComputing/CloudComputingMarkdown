Use case: scientific-educational
Asset type: concept figure for a Chinese undergraduate cloud computing textbook
Primary request: Create a container networking topology figure that visually separates two communication patterns: (1) inter-container communication via Docker DNS inside a virtual network, and (2) external access via host port mapping. The figure must make it visually obvious that the virtual network is an isolated space that external clients cannot directly enter.

Source context from the textbook:
Each container has its own Network Namespace with an independent IP, NIC, and routing table. Containers on the same Docker user-defined network can communicate using service names (e.g., "redis:6379"). Docker runs an embedded DNS server inside the network that resolves service names to container IPs. External clients (game players) cannot reach containers directly because the virtual network is invisible from outside. The only way for external traffic to enter is through port mapping (-p host_port:container_port), which forwards packets arriving at a host port into the target container.

Teaching goal:

The spatial separation between "inside the network" and "outside the host" must be immediately clear.
